## 

> 你觉得代码好看还是难看，那只是因为你熟悉或陌生。

软件设计原则：

- 不要重复
- 让方法保持简单，甚至简单到小白都能懂
- 面向接口编程，而不是实现
- 别因为下次需要在这次编程中实现
- 顶层询问原则，在模块的最顶层询问内容，而不是其中的一部分

组件开发推荐使用**强类型语言**，因为需要调用对应的 API 实现功能，强类型独有语法提示，类型提示。

只有当同一份代码使用过多次之后，再提取到工具中，视图上同理

## 命名规则

尽可能使用方法命名代替注释

```js
/**
 * 求和函数
 * @param {number} a 加数
 * @param {number} b 加数
 * @return {number} sum 和
 */
function getAB(a,b){
  return parseInt(a)+parseInt(b)
}

// 尽可能不使用注释
function sumString(a,b){
  return parseInt(a)+parseInt(b)
}
```
